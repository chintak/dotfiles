- Most files here are managed by the **dot CLI**: edit them in `~/git/dotfiles/configs/opencode/files/` (agents, skills, `opencode.jsonc`, `tui.jsonc`), then run `dot apply opencode` — never edit the live files/symlinks in this directory directly.
- Exception: `plugins/` is owned by the herdr integration (it overwrites it on update); `cli.json`, `service.json`, `node_modules/` are runtime state.
- **Persist credentials for the OpenCode daemon, not just the shell.** MCP servers and plugins run in the background service (`opencode serve --service`), which does not inherit shell-only exports; `{env:NAME}` in `opencode.jsonc` is resolved there. For any credential: put a *literal* value in `~/.env` (never `$(...)`), run `opencode service set env NAME "$NAME"`, then `opencode service stop && opencode service start`, and check `opencode api get /api/mcp`. This is the fix for an MCP failing with `HTTP 400 Authorization header is badly formatted` (empty `Bearer `).
