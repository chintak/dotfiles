- **Agent config is managed by the dot CLI** (source repo `~/git/dotfiles`). This file, the skills, and the MCP servers are written once in `shared/` and installed into both OpenCode (`~/.config/opencode/`) and Claude Code (`~/.claude/`). Tool-specific settings and agents live in `configs/opencode/files/` and `configs/claude/files/`. Edit the repo, then `dot apply opencode claude`; never edit the live symlinks or the store (`~/.local/share/dot/store/<name>/<version>/`) directly. After editing `shared/mcp.json`, run `shared/render-mcp.py` to regenerate both tools' MCP config.
- **Runtime state, not dot-managed:**
  - OpenCode: `plugins/` (owned by the herdr integration, which overwrites it on update), `cli.json`, `service.json`, `node_modules/`.
  - Claude Code: `settings.json`, `settings.local.json`, `~/.claude.json`, `plugins/`, `projects/`, and any `~/.claude/skills/` entry dot didn't install.
- **MCP credentials.** GitHub uses a fine-grained PAT in `GITHUB_PERSONAL_ACCESS_TOKEN`. Never use `GITHUB_TOKEN`: the gh CLI `gho_` token is unsupported, expires, and is a documented 401 cause. Keep MCP credentials out of `~/.env`. A missing or expired credential shows up as `HTTP 400 Authorization header is badly formatted` (an empty `Bearer `).
  - **OpenCode:** MCP servers run in the background service (`opencode serve --service`), which does not inherit shell-only exports, so `{env:NAME}` in `opencode.jsonc` resolves there. Persist credentials straight into the daemon: `opencode service set env GITHUB_PERSONAL_ACCESS_TOKEN "<fine-grained PAT>"` and `opencode service set env HF_TOKEN "$(cat ~/.cache/huggingface/token)"`. Then run `opencode service stop && opencode service start` and check `opencode api get /api/mcp`.
  - **Claude Code:** `dot apply claude` registers user-scope servers into `~/.claude.json`. Bearer tokens are fetched at connect time by `~/.config/dot/claude/bin/mcp-bearer.sh NAME`. It tries `$NAME`, then the login keychain (`security add-generic-password -U -a "$USER" -s dot-mcp-NAME -w`), then the OpenCode daemon env if OpenCode is installed. Check with `claude mcp list`.
- **Citations — every claim and recommendation traces to a source consulted in this session.** Nothing unsupported is presented as fact: not in chat, not in plans or context docs, not in PR bodies or review comments.
  - **A source** is an artifact you read or ran: a repo file (`path:line`), command/tool/MCP output, upstream source code, a docs page, RFC/spec, changelog or release notes, issue/PR/discussion, paper, or blog post. **Not** a source: model priors, another agent's unverified claim, or your own earlier message.
  - **Local sources read inline; external sources get an index.** Cite a local artifact as `path:line` at the claim; cite an external one as `[n]` at the claim and once at the end under `**Sources**` — `[n] Title — https://…`, reusing a number for a repeat citation. Omit the index when only local sources were used. The index is one line per entry, never prose.
  - **Mechanical nits** (formatting, a typo, an unused import) cite the file they came from (`path:line`) — no external source needed.
  - **The falsifiability line.** A claim checkable against an artifact is empirical and must be cited; a preference, taste, or prediction that no artifact can settle is a judgment and must be tagged `(judgment)`. `(judgment)` may never shield a falsifiable claim — when in doubt, treat it as empirical. Empirical: "GitHub returns `HTTP 400` on an empty Bearer token" (cite the doc or log); "`dot apply` re-copies every file, so a content-only change reaches the store with no version bump" (cite `dot` lines 222–248). Judgment: "a cache is the cheapest way to cut p95 here"; "this plan is not worth its opportunity cost".
  - **Design proposals are judgments and are never withheld.** Brainstorming, `Risks/unknowns` entries, and architecture preferences flow freely when tagged; the withhold rule bites only on asserted facts.
  - **Unsourceable fact → withhold, research once, drop.** About to assert a fact with no source? Write one line `Withheld: <the claim> — no source yet`, make at most one research excursion (≤3 tool calls: read the upstream code, fetch the docs, `gh pr view`, search), and if it is still unsourced, say it is dropped in one line and move on. Never leave it implied, never re-assert it as verified.
  - **Never fabricate a citation**: no URL you did not fetch, no file you did not read, no issue/PR/paper you did not open. If a citation cannot be re-located, say it is unverified.
