- Most files here are managed by the **dot CLI**: edit them in `~/git/dotfiles/configs/opencode/files/` (agents, skills, `opencode.jsonc`, `tui.jsonc`), then run `dot apply opencode` — never edit the live files/symlinks in this directory directly.
- Exception: `plugins/` is owned by the herdr integration (it overwrites it on update); `cli.json`, `service.json`, `node_modules/` are runtime state.
- **Persist credentials for the OpenCode daemon, not just the shell.** MCP servers and plugins run in the background service (`opencode serve --service`), which does not inherit shell-only exports; `{env:NAME}` in `opencode.jsonc` is resolved there. `GITHUB_PERSONAL_ACCESS_TOKEN` (a fine-grained PAT) lives in `~/.env`; `HF_TOKEN` is pulled from the hf CLI. Persist each for the daemon — `opencode service set env GITHUB_PERSONAL_ACCESS_TOKEN "$GITHUB_PERSONAL_ACCESS_TOKEN"`, `opencode service set env HF_TOKEN "$(cat ~/.cache/huggingface/token)"` — then `opencode service stop && opencode service start`, and check `opencode api get /api/mcp`. Never export `GITHUB_TOKEN` (the gh CLI `gho_` token is unsupported and a documented 401 cause). Failure mode of a missing/expired credential: an MCP returning `HTTP 400 Authorization header is badly formatted` (empty `Bearer `).
