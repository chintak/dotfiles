- Most files here are managed by the **dot CLI**: edit them in `~/git/dotfiles/configs/opencode/files/` (agents, skills, `opencode.jsonc`, `tui.jsonc`), then run `dot apply opencode` — never edit the live files/symlinks in this directory directly.
- Exception: `plugins/` is owned by the herdr integration (it overwrites it on update); `cli.json`, `service.json`, `node_modules/` are runtime state.
- **Persist credentials for the OpenCode daemon, not just the shell.** MCP servers and plugins run in the background service (`opencode serve --service`), which does not inherit shell-only exports; `{env:NAME}` in `opencode.jsonc` is resolved there. `github` uses OAuth — sign in once via `/mcps`. Header-auth servers pull their token from source and persist it for the daemon — `opencode service set env HF_TOKEN "$(cat ~/.cache/huggingface/token)"`, then `opencode service stop && opencode service start`, and check `opencode api get /api/mcp`. Never freeze a token into `~/.env`, and never export `GITHUB_TOKEN`: a left-over `GITHUB_TOKEN` is a documented cause of GitHub-MCP 401s (it also shadows gh's own auth). Failure mode of a missing/expired credential: an MCP returning `HTTP 400 Authorization header is badly formatted` (empty `Bearer `).
