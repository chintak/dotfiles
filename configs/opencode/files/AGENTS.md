- Most files here are managed by the **dot CLI**: edit them in `~/git/dotfiles/configs/opencode/files/` (agents, skills, `opencode.jsonc`, `tui.jsonc`), then run `dot apply opencode` — never edit the live files/symlinks in this directory directly.
- Exception: `plugins/` is owned by the herdr integration (it overwrites it on update); `cli.json`, `service.json`, `node_modules/` are runtime state.
- **Persist MCP credentials for the OpenCode daemon, not the shell.** MCP servers/plugins run in the background service (`opencode serve --service`), which does not inherit shell-only exports; `{env:NAME}` in `opencode.jsonc` is resolved there, so credentials must be persisted straight into the daemon: `opencode service set env GITHUB_PERSONAL_ACCESS_TOKEN "<fine-grained PAT>"`, `opencode service set env HF_TOKEN "$(cat ~/.cache/huggingface/token)"` — then `opencode service stop && opencode service start` and check `opencode api get /api/mcp`. Keep these out of `~/.env`, and never use `GITHUB_TOKEN` (the gh CLI `gho_` token is unsupported, expires, and a documented 401 cause). Failure mode of a missing/expired credential: an MCP returning `HTTP 400 Authorization header is badly formatted` (empty `Bearer `).
